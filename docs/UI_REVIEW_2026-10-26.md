# SOC workspace and employee upload review

Scope: reduce SOC information density, align copy and typography, preserve the
employee layout and existing security workflows. The review used the supplied
screenshots and current frontend implementation.

Follow-up corrections, exact theme/font values and the pending Administrator
dashboard review are in the [27 October update notice](UI_UPDATE_NOTICE_2026-10-27.md).

## Findings and changes

| Finding | Revision |
| --- | --- |
| Incidents mixed operational work with several analytics cards. | Incidents contains the queue and detail panel. Charts are under Insights → Overview; behavioral analysis is under Insights → Risk analysis. |
| Audit log repeated the page title and showed an uninterrupted list. | One visible title, short introduction, paged rows and a detail dialog for full context. |
| Long tables made labels, URLs and reasons compete for space. | Pagination, readable row spacing, wrapped previews and full details on selection. Sorting happens before pagination. |
| The donut's center label crowded its ring. | The number stays in the center; the label sits below the chart. Legend values remain aligned and accessible. |
| Auto-fitting analytics cards and entrance transforms made the workspace feel unsettled. | SOC uses explicit grid breakpoints, reserved card sizes and no card entrance transforms. Employee card/grid positions are retained. |
| Live rows could move while an analyst was reading them. | Pause feed freezes the displayed traffic snapshot. Collection and proxy protection continue; Resume shows the latest events. |
| Large Unknown alert counts resembled a threat backlog. | Needs review counts open Critical and employee-report alerts. Unknown traffic and other alerts remain available in their existing filters. |
| Stream connectivity looked like a guarantee of fresh data. | The status says Stream connected or Updates delayed. Partial refresh failures retain the prior data with a visible notice. |
| Threat intelligence showed default report scores as confidence. | The overview table omits that misleading column. A review dialog distinguishes provider scores from report/manual records without measured scores. Policy changes require a reason. |
| Sign-in history had device placeholders and a synthetic Low/Medium risk label. | It shows actual role, authentication activity, timestamp and success/failure. The count is events, not unique successful sign-ins. No new device-risk capability is claimed. |
| Inbox repeated large report/email cards and transport configuration. | Compact counts and paged lists; evidence opens on selection. Sending warnings remains available. |
| Employee Reflex text was uncolored and widely spaced. | Blue Reflex, Poppins, and normal wordmark spacing. |
| The file chooser exposed a default browser button. | A styled native input with Browse files, selected filename/size, Change file and Remove. Keyboard access, existing size limits and explicit VT consent are preserved. |

## Stability and scope

- Responsive changes when resizing the window or collapsing the sidebar are
  intentional. Data refreshes do not reorder the analytics card layout.
- Incoming live traffic can still prepend rows unless Pause feed is selected.
- Pagination retains all records in the loaded window; it does not silently remove
  records. A shrinking result set cannot leave a stale page that reappears later.
- No authentication, database, ML, proxy enforcement, exam grading or SMTP behavior
  was changed by this UI revision.
- No dependency was added. Upload files remain uninspected bytes until the existing
  explicit scan submission; selecting or clearing a file sends no upload request.

## Verification limits

activation. The checks include pagination, sorting, live-feed pause/resume, required
SOC reasons and file-selection/consent behavior.

the dashboard Docker build. The dashboard was recreated with the new image; all
